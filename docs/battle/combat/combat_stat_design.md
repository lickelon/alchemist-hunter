# 전투 스탯 설계 기준

## 0. 목적
- 이 문서는 전투 스탯 체계에 대해 합의된 기준만 정리한다.
- `docs/battle/battle_completion_plan.md`가 전투 전체 로드맵이라면, 이 문서는 그중 `스탯 모델` 파트의 source of truth다.

## 1. 설계 원칙
- `용병 / 호문`은 전투 피해 타입이 아니라 `계열 태그`다.
- 실제 전투 계산은 `물리 / 마법` 축을 기준으로 한다.
- 공격과 방어는 모두 `물리 / 마법`으로 분리한다.
- 전투 스탯은 단일 `power`가 아니라 개별 수치 집합으로 다룬다.
- 스탯 소유권은 `(직업, 티어, 랭크)` 기준 테이블에 둔다.
- `레벨`은 전투 스탯 전반을 올리지 않고 `체력`만 증가시킨다.

## 2. 전투 스탯 세트

### 2.1 초기 확정 스탯
- `HP`
- `MP`
- `물공`
- `물방`
- `마공`
- `마방`
- `속도`
- `치확`
- `치피`
- `명중`
- `회피`
- `상태적중`
- `상태저항`
- `물리관통`
- `마법관통`
- `흡혈`
- `회복력`
- `재생`
- `MP재생`

### 2.2 제외 스탯
- `강인`은 초기 스탯 세트에서 제외한다.
- `MP`는 스킬 시스템을 위한 전투 자원이다.
  - 이번 단계에서는 `최대MP`, `MP재생`, 스킬 정의를 모델에 반영한다.
  - 실제 스킬 선택 / MP 전량 소비 / 쿨다운 적용은 후속 combat loop 단계에서 구현한다.

### 2.3 유지력 스탯 의미
- `흡혈`: 가한 피해의 일부를 자기 체력으로 회복
- `회복력`: 자신이 발생시키는 치유/보호막 산출량 증폭
- `재생`: 턴 종료 또는 라운드 종료 기준의 고정 회복
- `MP재생`: 일반 공격 후 회복하는 정수 MP량

### 2.4 MP 사용 규칙
- 전투 시작 시 현재 MP는 0이다.
- 일반 공격 lifecycle 종료 후 `MP재생` 수치만큼 현재 MP를 회복한다.
- 현재 MP가 `최대MP`에 도달한 유닛은 다음 행동에서 액티브 스킬을 반드시 사용한다.
- 액티브 스킬 사용 시 현재 MP를 전부 소비한다.
- 액티브 스킬 사용 행동에서는 일반 공격 후 MP 회복을 적용하지 않는다.

## 3. 계열과 직업

### 3.1 계열 태그
- 기본 계열 태그는 2종이다.
  - `용병`
  - `호문`

### 3.2 계열 태그 사용처
- `대 용병`, `대 호문` 같은 취약/보너스 훅
- 장비 제한
- 향후 패시브 조건

### 3.3 하지 않는 것
- `용병 ↔ 호문` 전역 고정 상성 배율은 두지 않는다.
- 계열 태그를 전투 피해 타입처럼 직접 계산하지 않는다.

### 3.4 기본 전투 직업군
- 각 계열은 아래 4개 기본 전투 직업군을 가진다.
  - `전사`
  - `마법사`
  - `도적`
  - `궁수`

즉 초기 기본 직업군은 총 8개다.
- `용병 전사`
- `용병 마법사`
- `용병 도적`
- `용병 궁수`
- `호문 전사`
- `호문 마법사`
- `호문 도적`
- `호문 궁수`

### 3.5 전직 구조
- 티어 업 시 상위 전직 브랜치가 열릴 수 있는 구조로 설계한다.
- 이번 단계에서는 `전직 가능한 스키마`만 고정한다.
- 상위 전직 목록과 세부 트리는 후속 단계에서 채운다.

## 4. 스탯 소유권과 성장 규칙

### 4.1 스탯 소유권
- 기본 전투 스탯은 `(직업 × 티어 × 랭크)` 기준 테이블이 소유한다.
- 구현 방식은 `테이블 중심`으로 간다.
- 화면용 역할명은 그대로 쓰지 않고, 전투용 내부 식별값을 별도로 둔다.

### 4.2 레벨 규칙
- 레벨업으로 변하는 전투 스탯은 `HP`만이다.
- `HP`는 `직업별 고정 증가량` 테이블로 올린다.
- 나머지 전투 스탯은 레벨로 직접 증가하지 않는다.

### 4.3 랭크 규칙
- 랭크업은 현재 티어 내에서 전투 스탯 상승을 담당한다.
- 랭크는 `체력 포함 전 스탯` 상승 축으로 본다.

### 4.4 티어 규칙
- 티어업은 캐릭터의 근본 능력 상승을 담당한다.
- 허용:
  - `새 티어 1랭크`가 `이전 티어 최대랭크`보다 약할 수 있다.
- 필수:
  - 새 티어 진행 중, 최대랭크 도달 전 시점에 `이전 티어 최대랭크 수준을 반드시 넘어야 한다.`

## 5. 전투 입력 모델

### 5.1 방향
- 기존 `HeroProfile(id, name, power)` 단일 입력은 폐기 대상이다.
- 전투 엔진은 실제 전투 스탯 집합을 입력으로 받아야 한다.

### 5.2 모델 방향
- `BattleCombatStats` 또는 동등한 값 객체를 둔다.
- `HeroProfile`은 아래 둘 중 하나가 되어야 한다.
  - 실제 전투 스냅샷을 포함한 모델
  - 전투 스탯 집합을 직접 포함한 모델

### 5.3 전투력 요약값
- `전투력`은 남길 수 있다.
- 다만 `전투력`은 실제 전투 입력의 요약 파생값이어야 한다.
- 더 이상 원천 계산 모델이 되어서는 안 된다.

## 6. 이번 단계에 포함하지 않는 것
- 스킬 발동 로직
- 상태이상 세부 규칙
- 버프/디버프 상세 체계
- 최종 전직 트리
- 전투 밸런스 수치 확정

## 7. 구현 시 주의점
- 템플릿/레시피의 화면용 `roleLabel`을 내부 전투 키로 재사용하지 않는다.
- 전투용 직업 식별자는 별도 필드로 둔다.
- 장비/인챈트 보너스는 `BattleCombatStats` 계산 단계에서 합산한다.
- 캐릭터 타입, 티어, 랭크, 장비, 인챈트가 모두 동일한 전투 스탯 계산 경로를 타야 한다.
