# UI 디자인 시스템 기준

## 목적
공통 UI 컴포넌트의 역할을 명확히 해서 feature별 화면이 서로 다른 패턴으로 갈라지는 것을 막는다.
이 문서는 새 UI를 만들거나 기존 시트/모달 구조를 정리할 때 우선 기준으로 본다.

## 기본 원칙
- 큰 작업 표면은 바텀시트로 연다.
- 바텀시트 안에서 추가 상세, 확인, 결과 보기는 다이얼로그 모달로 연다.
- 바텀시트에서 다른 바텀시트를 다시 열지 않는다.
- 정보 표시와 주요 액션은 같은 표면 안에서 끝낸다.
- 닫기, 확인, 등록 같은 종료 액션은 하단 고정 영역에 둔다.
- 플로팅 닫기 버튼은 기본 패턴으로 쓰지 않는다.

## 컴포넌트 역할

### AppBottomSheet
탭 화면이나 카드에서 여는 큰 작업 표면이다.

사용 예:
- 편성
- 제작
- 상점
- 장비/캐릭터 상세
- 전투 현황
- 작업실 큐

기준:
- 화면 높이의 상한을 가진다.
- 긴 내용은 내부 body에서 스크롤한다.
- footer는 스크롤 영역 밖에 고정한다.
- 기본 닫기 버튼은 footer에 둔다.

### AppSheetLayout
바텀시트 내부의 표준 구조다.

구성:
- `title`: 시트 제목
- `header`: 요약, 상태, 필터 같은 상단 보조 정보
- `body`: 목록, 폼, 상세 본문
- `footer`: 닫기와 주요 액션

기준:
- 정보성 시트는 footer에 `닫기` 단일 버튼을 둔다.
- 액션 시트는 footer에 `닫기`와 주요 액션을 함께 둔다.
- 주요 액션은 오른쪽 또는 하단에서 더 강한 버튼 스타일을 쓴다.
- body 안에 닫기 버튼을 넣지 않는다.

### AppDialogLayout
바텀시트 안에서 여는 보조 모달 표면이다.

사용 예:
- 상세 설명
- 적 정보 / 드롭 상세
- 최근 전투 기록
- 작업 전 확인
- 짧은 결과 요약

기준:
- 다이얼로그는 하나의 짧은 목적만 가진다.
- 긴 목록이나 복잡한 작업 흐름은 다이얼로그로 만들지 않는다.
- actions에는 `닫기`, `확인`, `교체` 같은 종료 액션만 둔다.
- 다이얼로그에서 다시 바텀시트나 다이얼로그를 열지 않는다.

## 중첩 규칙

허용:
- 화면 → 바텀시트
- 화면 → 다이얼로그
- 바텀시트 → 다이얼로그

금지:
- 바텀시트 → 바텀시트
- 다이얼로그 → 바텀시트
- 다이얼로그 → 다이얼로그

## 닫기 버튼 기준
- 정보성 바텀시트는 footer의 전체 폭 `닫기` 버튼을 기본으로 한다.
- 액션 바텀시트는 `닫기`와 주요 액션을 같은 footer에 배치한다.
- 긴 정보성 시트는 상단 우측 `X`를 보조로 둘 수 있다.
- 플로팅 닫기 버튼은 콘텐츠, 스크롤, 주요 액션과 겹치기 쉬우므로 쓰지 않는다.

## 적용 순서
1. `AppSheetLayout`에 footer 구조를 추가한다.
2. 정보성 바텀시트부터 footer `닫기` 버튼을 적용한다.
3. 바텀시트 안에서 다시 바텀시트를 여는 흐름을 다이얼로그로 바꾼다.
4. 액션 바텀시트는 footer에 `닫기`와 주요 액션을 함께 정리한다.

## 우선 정리 대상
- 전투 현황 시트 안의 적 정보 / 드롭 상세
- 전투 현황 시트 안의 최근 기록
- 작업실 추출 시트 안의 재료 상세
- 제작/포션 상세에서 다시 여는 옵션 표면
