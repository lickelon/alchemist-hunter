# 개발 계획 v3

## 0. 문서 목적
- 이 문서는 `development_plan_v2.md`의 모순과 오래된 이행 체크리스트를 걷어내고, 현재 구현 기준의 단일 기준 문서로 사용한다.
- 앞으로의 작업은 "예전 구조를 어떻게 옮길지"가 아니라 "지금 있는 구조 위에서 무엇을 완성할지" 기준으로 적는다.
- 구조 원칙은 `docs/project_structure_principles.md`를 따른다.

## 1. 현재 제품 정의
- 현재 앱은 `Town / Workshop / Characters / Battle` 4탭 구조다.
- 제품의 중심 루프는 다음 순서다.
  1. `Battle`에서 골드, 정수, 재료, 캐릭터 XP를 획득한다.
  2. `Town`에서 상점 구매, 포션 판매, 장비 제작, 용병 고용, 마을 스킬트리를 진행한다.
  3. `Workshop`에서 재료 추출, 포션 제조, 장비 인챈트, 호문쿨루스 부화, 작업실 보조 슬롯, 작업실 스킬트리를 진행한다.
  4. `Characters`에서 용병/호문쿨루스 성장, 장비 관리, 배치 상태를 확인한다.
- 전역 시간 진행은 `app/session`의 sync 파이프라인과 시간 가속 버튼으로 처리한다.

## 2. 현재 구조 기준

### 2.1 앱 구조
- 앱 셸은 `lib/app/app.dart`에 있다.
- 전역 세션 상태 저장소와 sync 파이프라인은 현재 `lib/app/session/*`에 있다.
- 기능별 코드는 `lib/features/<feature>` 아래 `presentation / domain / data`로 나뉜다.
- 재사용 UI와 테마는 `lib/common/*`에 둔다.

### 2.2 상태 소유권
- `Town`은 상점, 판매, 장비 제작, 용병 고용, 마을 스킬트리의 소유자다.
- `Workshop`은 추출, 제조, 인챈트, 부화, 작업실 보조 슬롯, 작업실 스킬트리의 소유자다.
- `Characters`는 성장, 장비 장착, 배치 표현의 소유자다.
- `Battle`은 자동 전투, 원정 상태, 전투 보상, 스테이지 배치의 소유자다.
- feature 비즈니스 규칙은 각 feature `domain`에 있고, 전역 세션은 규칙을 직접 소유하지 않는다.

## 3. 재화와 자원 규칙

### 3.1 현재 재화 정의
- 골드 (`Gold`)
  - Town 경제 재화
  - 현재 획득처: 전투 보상, 포션 판매
  - 현재 사용처: 상점 구매, 상점 강제 갱신, 용병 고용, 마을 스킬트리 일부 비용
- 정수 (`Essence`)
  - Workshop 운영 재화
  - 현재 획득처: 전투 보상
  - 현재 사용처: 호문쿨루스 부화
- 명성 (`townInsight`)
  - Town 성장 재화
  - 현재 획득처: 포션 판매
  - 현재 사용처: 마을 스킬트리
- 신비 (`arcaneDust`)
  - Workshop 성장 재화
  - 현재 획득처: 재료 추출 완료 보상
  - 현재 사용처: 작업실 스킬트리, 호문쿨루스 부화
- 원소 재고 (`extractedTraitInventory`)
  - Workshop 전용 제작 자원
  - 현재 획득처: 재료 추출
  - 현재 사용처: 포션 제조, 작업실 스킬트리 일부 비용, 호문쿨루스 부화 원소 비용
- 재료 재고 (`materialInventory`)
  - 공통 재료 자원
  - 현재 획득처: Town 상점 구매, Battle 드롭
  - 현재 사용처: 장비 제작, 재료 추출, 호문쿨루스 부화, 캐릭터 티어업
- 다이아 (`diamonds`)
  - 현재 HUD 플레이스홀더
  - 실제 소비처와 확장 규칙은 아직 미구현

### 3.2 현재 구현 기준의 source / sink 매트릭스

| 자원 | 주요 source | 주요 sink | 비고 |
| --- | --- | --- | --- |
| 골드 | 전투, 포션 판매 | 상점 구매, 강제 갱신, 용병 고용, Town 스킬트리 | 실패 전투는 무보상이며 패널티도 없다 |
| 정수 | 전투 | 부화 | 현재 Workshop 일반 행동 비용으로 넓게 쓰이지 않음 |
| 명성 | 포션 판매 | Town 스킬트리 | Town 전용 성장 재화 |
| 신비 | 추출 완료 수령 | Workshop 스킬트리, 부화 | Workshop 전용 성장 재화 |
| 원소 | 추출 | 제조, Workshop 스킬트리, 부화 | 통화라기보다 제작 재고에 가깝다 |
| 재료 | 상점, 전투 | 제작, 추출, 부화, 티어업 | 양 feature에서 공유 사용 |

### 3.3 현재 문서화 기준
- `Town 재화 = 골드만`, `Workshop 재화 = 정수만` 같은 단순 규칙은 더 이상 사용하지 않는다.
- 현재 구현은 "기본 경제 재화"와 "성장 전용 재화"가 분리된 구조다.
- 현재 기준에서 중요한 구분은 아래와 같다.
  - `Town` 기본 경제 축: 골드
  - `Town` 성장 축: 명성
  - `Workshop` 운영 축: 정수
  - `Workshop` 성장 축: 신비
  - `Workshop` 제작 축: 원소

## 5. v2에서 정리된 모순

### 5.1 재화 규칙 모순 제거
- `v2 3.0.1`의 "`Town = 골드`, `Workshop = 정수` 단일 재화 구조"는 현재 구현과 맞지 않는다.
- 현재 구현은 아래처럼 동작한다.
  - `Town`: 골드 + 명성
  - `Workshop`: 정수 + 신비 + 원소
- 특히 아래 내용은 `v2`의 표현이 잘못 단순화한 부분이다.
  - 장비 제작은 현재 골드가 아니라 재료를 소비한다.
  - 작업실 스킬트리는 신비 + 원소를 소비한다.
  - 호문쿨루스 부화는 정수 + 신비 + 재료 + 원소를 소비한다.

### 5.2 구 UI 마이그레이션 체크리스트 제거
- `Weapons` 단일 화면 기준의 역할 정의는 현재 상태를 설명하지 못한다.
- 현재 앱은 이미 `Town / Workshop / Characters / Battle` 4탭 기준으로 동작한다.
- 따라서 `v3`에서는 "예전 화면을 어디로 옮길지"가 아니라 "현재 각 탭이 무엇을 책임지는지"만 유지한다.

### 5.3 캐릭터 화면 상태 정정
- `v2`의 "용병 / 호문쿨루스 서브탭 분리 완료"는 현재 구현과 맞지 않는다.
- 현재는 두 타입을 한 화면에서 통합 리스트로 보여준다.

### 5.4 큐 슬롯 규칙 정정
- `v2`의 "초기 2칸, 다이아 확장"은 현재 구현과 맞지 않는다.
- 현재 구현은 `기본 4칸 + Workshop 스킬트리 보너스 + 작업실 보조 슬롯 보너스` 구조다.
- 다이아 확장은 아직 backlog다.

### 5.5 v2 잔재 보류 판단
- 용병 계약 상태는 현재 별도 계약 기간, 만료, 유지비 모델이 없으므로 구현 backlog에 넣지 않는다.
- 현재 필요한 용병 상태 표기는 전투 배치, 작업실 배치 불가, 대기 상태로 제한한다.
- 호문쿨루스 친화 특성은 현재 `originRecipeId`, 역할, 작업실 보조 효과로 충분하므로 후속 보류 항목으로 둔다.
- 캐릭터 상세에서 배치 전환은 현재 주 흐름이 아니며, 배치 변경은 Battle 편성 시트와 Workshop 보조 슬롯에서 처리한다.
