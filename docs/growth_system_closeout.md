# 성장 시스템 마감 정책

## 1. 목적
성장 시스템의 남은 미정 항목을 현재 구현 기준에서 닫는다.

현재 성장 축은 `레벨 / 랭크 / 티어`, 장비 장착, 전투 배치, 작업실 보조 배치, Town / Workshop 스킬트리까지 구현되어 있다. P4 성장 시스템 마감은 신규 기능을 늘리는 작업이 아니라, 지금 넣으면 위험한 정책을 보류 또는 후속 과제로 명확히 분리하는 작업이다.

## 2. 스킬트리 리스펙 정책
현재는 스킬트리 리스펙을 구현하지 않는다.

보류 이유는 다음과 같다.

- 스킬트리 비용, 효과, 노드 테이블이 아직 밸런스 조정 대상이다.
- 저장 버전과 콘텐츠 버전 정책이 아직 없다.
- 환불률, 재화 환급, 선행 노드 롤백 규칙을 지금 고정하면 이후 데이터 변경과 충돌한다.

나중에 구현할 경우의 기준은 다음과 같다.

- Town 스킬트리와 Workshop 스킬트리는 서로 독립적으로 리스펙한다.
- 다른 트리의 재화로 환급하거나 전환하지 않는다.
- 리스펙은 전체 트리 단위로 먼저 도입하고, 단일 노드 리스펙은 후순위로 둔다.
- 환불률은 밸런스 데이터가 안정화된 뒤 별도 문서에서 정한다.
- 저장 버전 정책이 들어가기 전에는 리스펙 UI를 노출하지 않는다.

## 3. 용병 해고 / roster 정리 정책
현재는 용병 해고나 캐릭터 삭제를 구현하지 않는다.

보류 이유는 다음과 같다.

- 캐릭터는 장비, 전투 배치, 작업실 보조 배치와 연결된다.
- 삭제형 기능은 장비 자동 해제, 배치 해제, 진행 중 작업 참조 정리 규칙이 필요하다.
- 현재 roster 규모에서는 삭제 기능보다 성장/전투 루프 완성도가 우선이다.

나중에 구현할 경우의 기준은 다음과 같다.

- 즉시 삭제보다 `보관 / 비활성` 상태를 먼저 검토한다.
- 전투 배치 중인 캐릭터는 정리할 수 없다.
- 장비를 착용 중인 캐릭터는 먼저 장비를 해제해야 한다.
- 작업실 보조 슬롯에 배치된 호문쿨루스는 먼저 배치를 해제해야 한다.
- 삭제형 기능을 도입할 경우 되돌릴 수 없는 조작임을 UI에서 명확히 표시한다.

## 4. 캐릭터 화면 UX 정책
현재는 용병과 호문쿨루스를 한 화면의 통합 카드 리스트로 유지한다.

분리형 서브탭을 지금 도입하지 않는 이유는 다음과 같다.

- 현재 핵심 사용 흐름은 캐릭터 타입 분리보다 배치 상태, 성장 가능 여부, 장비 상태 확인이 중요하다.
- 두 타입의 공통 성장축이 이미 동일한 카드 구조로 표현된다.
- 리스트 규모가 아직 탭 분리를 강제할 정도로 크지 않다.

추후 캐릭터 수가 늘어나면 서브탭보다 먼저 정렬과 필터를 검토한다.

우선 검토 순서는 다음과 같다.

- 배치 상태 필터
- 성장 가능 필터
- 캐릭터 타입 필터
- 레벨 / 랭크 / 티어 정렬

## 5. 현재 완료 기준
성장 시스템 마감의 현재 완료 기준은 다음과 같다.

- 스킬트리 리스펙은 보류 정책으로 닫는다.
- 용병 해고와 roster 삭제는 보류 정책으로 닫는다.
- 캐릭터 화면은 통합 리스트 유지로 결정한다.
- 위 세 항목은 구현 backlog가 아니라 저장 정책과 밸런스 안정화 이후 재검토 항목으로 둔다.
